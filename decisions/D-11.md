# D-11 — Format : HTML pour le visuel sortant, Markdown pour la matière

## Contexte

Un gabarit HTML rempli à la main est un anti-patron classique : il ne survit pas au deuxième
usage et diverge de sa source dès la première correction.

## Décision

> Le HTML est le format des livrables **visuels destinés à sortir du projet**. Le Markdown
> reste celui de la matière première et des documents de travail.
>
> Ce n'est pas un remplacement : la source reste versionnable, diffable, lisible en revue ; le
> HTML en est une **projection**, régénérable, jamais éditée à la main.

## Conséquences

> Tout livrable HTML sortant est produit par un générateur, jamais saisi. Un gabarit HTML
> qu'on remplit à la main est un anti-patron.

## Statut corpus (circuit D-13)

`REGLES-PROJET.md` §G la classe « couverte » avec D-08→D-10 : mécanisme livrable, pas socle
projet — porté par `references\BEST-PRACTICES-HTML.md`.

## Vérification (TF-0109)

Non mécanisable : distinguer un HTML **généré** d'un HTML **saisi à la main** suppose de
connaître le générateur d'origine — cette information n'est pas visible dans le fichier
produit lui-même (pas de métadonnée de provenance prévue par la décision). Un HTML
statiquement bien formé peut avoir été tapé à la main sans que rien ne le trahisse. Déclarée
`SANS_OBJET` avec sa raison plutôt qu'ignorée.
