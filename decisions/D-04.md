# D-04 — Taxonomie des types : liste ouverte, registre tenu dans un fichier

## Contexte

Les versions précédentes du document de décisions tenaient la liste des `<Type>` admis dans
un tableau Markdown — deux copies d'une même liste divergent à la première correction.

## Décision

> La liste des `<Type>` reste ouverte, mais tout type nouveau est **ajouté au référentiel**
> au lieu d'être improvisé.
>
> **Le référentiel est un fichier** : `registre-types.json`, source unique. Il porte, pour
> chacun des **23 types admis**, son objet, ses graphies alternatives observées et son
> premier exemplaire quand l'inventaire de Phase 1 l'a relevé. Le tableau qui tenait lieu de
> registre dans les versions précédentes de ce document est supprimé.

## Conséquences

> Ajouter un type se fait dans `registre-types.json`, dans un commit qui le motive — pas dans
> un nom de fichier.

## Statut corpus (circuit D-13)

Encodée par le pilot à la règle 25 de `REGLES-PROJET.md` le 11/08 (TF-0084) — registre passé
en version 1.1.0, complété sur usage réel (29 types au 11/08 ; 29 dans le registre courant,
comparaison insensible casse/accents).

## Vérification

Mécanisée depuis l'origine de l'oracle : type absent du registre (`rouge-d04-type-inconnu`).
Non touchée par TF-0109 (déjà couverte). Non jugé par l'oracle : la pertinence du `<Type>`
choisi (le registre dit qu'il existe, pas qu'il est le bon — `non_juge[]`).
